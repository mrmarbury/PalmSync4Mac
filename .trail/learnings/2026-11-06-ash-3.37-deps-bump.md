# ash 3.37 bump: undeclared arg() rejected; ash_sqlite --dry-run deletes dev migrations

Date: 2026-11-06
Touches: mix.lock, config/config.exs, lib/palmsync4mac/entity/event_kit/calendar_event.ex, priv/repo/migrations/, priv/resource_snapshots/

## Decided
- ash 3.13→3.37.3 spike (#47) is viable: only two migration changes needed —
  `config :ash, default_string_length_count: :codepoints` (hard requirement, engineer
  chose :codepoints; inert today, no resource uses string length constraints) and
  declaring `argument(:new_last_modified, :utc_datetime)` +
  `argument(:new_alarms_seconds, {:array, :integer})` on
  `CalendarEvent.create_or_update` (default allow_nil? true keeps pre-3.37 nil-binding
  semantics for seed fixtures that don't set them).
- DatebookAppointment @spec self-reference by bare alias (`DatebookAppointment.t()`)
  is a pre-existing dialyzer unknown_type on main — left alone per engineer; follow-up
  ticket also adds `mix dialyzer` to CI (absent from .github/workflows/elixir.yml).

## Tried and ruled out
- `allow_nil?: false` on the new arguments: breaks every fixture that seeds
  CalendarEvents without set_argument (sync status + appointment worker tests) with
  Ash.Error.Changes.Required. Not faithful to 3.13 behavior.
- `mix ash_sqlite.generate_migrations --dry-run` as a drift check: DO NOT USE. Our
  migrations/snapshots are `_dev`-suffixed, so the generator's consolidate path removes
  them; `--dry-run` suppresses writing the new files but NOT the removal. It emptied
  priv/repo/migrations/ and priv/resource_snapshots/ mid-session (restored with
  `git restore`). Use `--check` only — and note it fails with "dev migrations remain"
  on main too; that message is NOT drift.

## Watch out
- ash >= 3.37 rejects `set_argument/3` on undeclared names (Ash.Error.Invalid.NoSuchInput)
  and binds NULL in upsert SQL for `^arg()` references in upsert_condition/atomic_update.
  Any `^arg(:x)` in action expressions now needs a matching `argument` declaration.
- typed_struct_nimble_options "Cannot automatically derive validation_type" warnings
  and the NIF `uint64_t*`/`unsigned long*` warnings are pre-existing (pinned deps
  typed_struct 0.3.0), NOT from the bump — don't chase them during future bumps.
